## Six-month roadmap

### Month 1 — Rust and elementary problem solving

- Rust setup and program structure
- Variables, types, conditions, loops and functions
- Ownership and borrowing fundamentals
- Arrays, vectors, strings, tuples, structs and enums
- `Option`, `Result`, iterators and collections
- Sorting and competitive-programming input/output
- Complexity analysis
- Basic mathematics, arrays, strings, simulation and frequency counting
- Target: 50–70 beginner problems, adjusted for comprehension

### Month 2 — Essential problem patterns

- Prefix and suffix sums
- Two pointers and sliding windows
- Binary search and binary search on the answer
- Hash maps and sets
- Stacks, queues and deques
- Greedy reasoning
- Bit manipulation
- Elementary number theory
- Begin regular contests

### Month 3 — Recursion, graphs and trees

- Recursion and backtracking
- BFS and DFS
- Grid traversal and connected components
- Trees and tree traversal
- Topological sorting and bipartite graphs
- Disjoint-set union
- Shortest paths and minimum spanning trees

### Month 4 — Dynamic programming

- Recognizing dynamic-programming structure
- State and transition design
- Memoization and tabulation
- One-dimensional and grid DP
- Knapsack and subsequence patterns
- Introductory interval, bitmask and tree DP

### Month 5 — Intermediate algorithms and data structures

- Fenwick trees and segment trees
- Sparse tables and coordinate compression
- Modular arithmetic, sieves and factorization
- Combinatorics
- Tries and string algorithms
- Lowest common ancestor
- Intermediate graph problems
- Mixed, unlabeled practice

### Month 6 — Contest specialization

- Frequent timed and virtual contests
- Disciplined upsolving
- Weak-topic repair
- Speed and implementation work
- Advanced variations of familiar patterns
- Personal Rust template refinement
- Weekly coding-interview mocks

## Learning protocol

For each important topic:

1. Learn the intuition and derive the idea.
2. Trace examples manually.
3. Implement the technique in Rust.
4. Solve one guided problem.
5. Solve several related problems independently.
6. Review reasoning, correctness, complexity and code quality.
7. Repeat selected problems through spaced revision.
8. Encounter the technique later in an unlabeled mixed set or contest.

## Problem-status definitions

| Status | Meaning |
|---|---|
| Independent | Correct approach and implementation without hints |
| Minor hint | Small observation supplied; core solution derived independently |
| Major hint | Algorithm or central direction supplied |
| Editorial | Solution explanation was required |
| Revisit | Not yet reproducible independently |
| Mastered | Solved independently again after an appropriate delay |

Reading an editorial does not make a problem mastered. The solution must be reimplemented without copying and followed by a related or repeated problem.

## Interview-question protocol

For each dedicated interview question:

1. Clarify requirements and constraints.
2. Work through examples.
3. Describe a brute-force solution.
4. Explain its limitation.
5. Derive an optimized approach.
6. Explain why it is correct.
7. State time and space complexity.
8. Implement cleanly in Rust.
9. Test normal cases and edge cases.
